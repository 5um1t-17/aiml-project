Units and source limitations

Annual income: enter a full yearly amount. Monthly equivalent is annual income ÷ 12.

Loan and assets: enter full values in consistent source units. The publisher metadata does not identify the currency; the website does not imply a rupee/dollar conversion.

Loan term: source values 2, 4, …, 20 are interpreted as years by the explicit project choice. The publisher metadata does not establish this unit, so repayment estimates and derived term ratios carry this assumption.

Provenance: the source description does not establish an originating institution or whether the records were collected or generated. A high holdout score on this file is not evidence of real bank accuracy.

Training and evaluation

  1. Strip whitespace from source headers and categories.
  2. Treat {{ metrics.audit.negative_asset_values.residential_assets_value }} negative residential-asset values as missing; keep all source rows and labels.
  3. Use a stratified 80/20 split: {{ metrics.train_rows }} training and {{ metrics.test_rows }} holdout records.
  4. Fit medians, numeric scaling and categorical encoding inside each training fold.
  5. Compare Logistic Regression, Decision Tree and Random Forest, with source-only baselines and financial-ratio candidates.
  6. Select using training-only five-fold CV balanced accuracy. Report the individual models and their equal-weight mean on the new holdout.
  7. Keep those evaluation models separately. Clone the selected pipelines and fit all three final website models on every one of the {{ metrics.production_train_rows }} source rows.

Website model version: {{ metrics.model_version }}. Displayed test metrics apply to the separate evaluation models; the final all-row models have no independent test measurement. CV scores include selection optimism. The holdout is not external validation, and percentages are uncalibrated scores.

Staff review and stored history

Every application starts pending. Staff manually record Accept, Reject or Keep pending, with reviewer details and notes. Model scores do not record a final decision.

Repayment arithmetic, training ranges and rare terms produce review prompts. Passing these checks does not certify reliability.

The configured database stores the canonical source inputs as JSON with a schema and model version. Previous mortgage-format records keep their original inputs and scores; the new models never infer missing CIBIL or asset values for those records.

Four fictional defaults cover both dataset options: a personal loan, previous defaults, an asset-backed application awaiting review, and a repayment-capacity warning. All scores come from the trained models. The first two include clearly marked simulated staff acceptance/rejection reviews; the remaining two stay pending. They are separate from training data. Reviewer names and roles are self-entered in this local demo, not authenticated bank accounts.
